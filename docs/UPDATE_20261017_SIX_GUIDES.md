# 8207 V29 六段独立关键帧 Guide（2026-10-17）

本更新为六段导演台增加默认关闭、逐段隔离的单张用户关键帧。用户可在当前段上传图片，并按绝对帧、倒数帧或秒指定位置。未启用时，六段继续使用原执行图。

## 使用方法

在所需提示词卡片打开“本段关键帧”，上传图片，选择位置类型并输入位置。第4段需要倒数第88帧时，选择“倒数第N帧”并填 `88`；界面按当前实际生成帧数显示编译帧号。243帧编译为155，362帧编译为274。正向帧索引从0开始，倒数从1开始，秒数按24fps四舍五入到最近帧。

普通Native接续先按裁剪后的可见范围解析位置，再加39帧保护区偏移。Clean Rebase和独立起始不加偏移。Clean Rebase自动首帧接续Guide仍由原链生成，用户中段Guide另接在最终BasicGuider conditioning上；Clean Rebase首帧位置与用户帧冲突时提交前报错。启用用户Guide时，旧H3GuideTimeline保持旁路，避免其与连续生成封装形成循环。

每段设置随工作流保存，并在对应段执行快照中冻结。图片来源、SHA、段号、实际帧和快照身份在提交前及执行图中再次核对；图像或帧位置变化会改变PreBake/Fallback依赖身份，阻止旧结果误复用。上传失败、图片丢失、越界或执行图被改写时，提交前拒绝。

## 验收状态

- `GUIDE_ROUTING=PASS`：56项CPU检查、11项PreBake回归；真实前端保存/刷新/载入/失败快照恢复隔离；243与362帧的完整Managed图分别通过8207服务端 `execution.validate_prompt`。
- 243帧倒数88→模型帧155；362帧倒数88→模型帧274；普通Native可见帧24→模型帧63。
- Clean Rebase自动首帧0与用户帧155/274同时进入最终conditioning。六段全部关闭时，12种旧缓存/Fallback图与原编译器逐图相同。
- `GUIDE_VISUAL_GPU=HOLD`：未提交GPU任务。接收者需由用户手动生成并观看，确认关键帧视觉生效与转场自然后，才能更新视觉验收状态。
- 长歌曲、原曲锁定、音频起点、跨组六段、Native39、播放器回填和合并文件未在此轮做GPU回归；既有验收等级继续按各自记录，不由Guide CPU检查代替。
