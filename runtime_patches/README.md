# 8207 隔离宿主修复

`dedup_custom_nodes.py <隔离宿主目录>` 修复同一路径被列举两次导致 Sidecar 重复注册队列守卫的问题。它只接受已知原行，先备份，再按真实路径及大小写归一化去重。不同目录均保留。停止隔离宿主后应用；不要对正式生产环境应用本实验修复。

`winerror64_20261019` 是原有、进程内的 Windows IOCP 修复。本轮未改其算法。仅当 `H3_INSTANCE_ID=h3-lab`、入口为 main.py、参数端口 8207 时激活；还核对 candidate 文件 SHA256 和 CPython accept/serving 实现指纹。已测试解释器为 CPython 3.13.14；未知实现明确拒绝。它不修改 Python 标准库，不影响其它实例。

在该隔离进程的环境变量中将此目录加入 `PYTHONPATH`，不要修改系统级环境变量；启动日志应显示 `H3_8207_IOCP_ACCEPT_REPAIR=INSTALLED`。WinError64 接受连接失败会记录重挂接，新请求、监听及持续 WebSocket 才是可用性证据。连接关闭后的 WinError10054 回调警告不能单独证明监听丢失。

接收方若不使用上述固定身份及版本，不应自行放宽指纹门；需要在自己的隔离环境单独验证。源码完整性检查与本机稳定性观察不能替代接收方运行验收。

固定上游宿主若已使用唯一base_path节点根，去重工具识别该已知原行并保持字节不变；不添加第二个目录。未知实现仍拒绝。
